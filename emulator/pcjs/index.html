86TO88 / ORIGINAL BINARY, NEW BRIDGE

Windows 3.1 Minesweeper.
Windows 3.0 underneath.

The game is Microsoft's original, unmodified WINMINE.EXE. The open-source WM88 bridge translates file reads in memory; Windows and the game are not reimplemented.

This browser fixture emulates an 80286, not an 8088. Windows is launched with WIN /R (real mode), with 640 KiB conventional RAM and no extended RAM. This is a compatibility/gameplay demo, not an 8088 hardware proof. The project's real Tandy 1000 EX report and its earlier emulator startup failures are separate evidence.

1 · Wait for boot

DOS loads the bridge, runs the TEST88 and RTEST2 suites, then opens the game. Boot speed depends on your device.

2 · Play the original

Click inside the screen. Left-click reveals; right-click flags. F2 starts a new game. If a click first focuses the emulator, click again.

3 · Inspect the evidence

Local input hashes & preparation manifest. Source files are never edited. Reload discards session changes and starts fresh.

Original EGA display: the dark-red digit segments are dithered by the stock display driver. Their shapes match the original game bitmap exactly. The default 1× speed preserves normal timer pace; the Speed button changes emulated time too. The guest mouse uses relative movement: steer its visible arrow to a cell, then click. If Full screen is unavailable, continue in the page.

What this proves — and what it doesn't

The browser executes the original DOS, Windows 3.0 and Windows 3.1 Minesweeper code. WM88TSR translates the known 27,776-byte specimen and the 361-byte SHELL.DLL shim supplies ShellAbout. A working 286 run does not prove 8088 instruction compatibility or timing. A passing DOS test is not proof of complete Windows startup or gameplay.

PCjs session changes are memory-only here. Reload restores the generated disk; no automatic session resume is enabled. A Reset restarts the guest with its current in-memory disk. Do not publish this generated directory: it contains third-party DOS/Windows and ROM media.
